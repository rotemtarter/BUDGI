# MILESTONES.md — Budgi

## מטרת המסמך

מסמך זה מגדיר את אבני הדרך לפיתוח MVP של Budgi. החלוקה מבוססת על `PRD.md`, `ARCHITECTURE.md` ו-`DESIGN.md`, ומעדיפה `Vertical Slices`: בכל אבן דרך נמסרת יכולת משתמש עובדת, מקצה לקצה, שניתן לבדוק ולאשר באופן עצמאי.

יש לבצע את אבני הדרך לפי הסדר. אין להתחיל אבן דרך חדשה לפני שהמשתמש בדק ואישר את הקודמת.

## עקרונות ביצוע

1. **סדר מחייב:** יש לפתח את ה-Milestones לפי הסדר המופיע במסמך.
2. **עצירה לאישור:** בסיום כל Milestone יש לעצור ולדווח לפי פורמט התגובה שב-`CLAUDE.md`, כולל סטטוס לכל סעיף ב-`Definition of Done`.
3. **אין מעבר אוטומטי:** אין להתחיל את ה-Milestone הבא ללא אישור של המשתמש.
4. **Database Migrations:** כל שינוי בסכמת Database ייווצר כ-SQL migration חדש ב-`supabase/migrations/`, ויוחל וייבדק מול `budgi-dev` בלבד.
5. **Production:** עד Milestone 9 אין סביבת Production כלל. דחיפה ל-`main` יוצרת רק Preview המחובר ל-`budgi-dev` (ראו ARCHITECTURE 7.3, ADR-2).
6. **אבטחת סביבות:** אין להשתמש בנתוני משתמשים אמיתיים ב-Development, ואין להכניס Secrets ל-Git או לקוד Frontend.
7. **בדיקות:** יש להוסיף בדיקות אוטומטיות לאורך הפיתוח: `Vitest` ל-Unit/Integration/RLS, ו-`Playwright` ל-End-to-End באמצעות משתמשי הבדיקה (ARCHITECTURE 8.1). התחברות Google נבדקת ידנית.
8. **שמירה על Scope:** אין להוסיף יכולות שאינן מוגדרות ב-PRD, או מסכים שאינם מתוארים ב-DESIGN.

## Milestone 1 — הקמת הפרויקט ותשתיות ✅

### מטרה
להקים בסיס טכני עובד ל-Budgi: אפליקציית Web, סביבת פיתוח, מסד נתונים לפיתוח וגרסת Preview, בלי פיצ'רים עסקיים.

### מה יש לממש
- פרויקט `Next.js` עם `App Router`, `React` ו-`TypeScript` ב-Repository הקיים.
- `Tailwind CSS`, `shadcn/ui`, מבנה תיקיות לפי ARCHITECTURE 2.3, ו-`Vitest` ו-`Playwright`.
- בסיס עיצובי לפי `DESIGN.md`: הגופנים Plus Jakarta Sans ו-Rubik, צבעי המותג כולל Button Gradient, RTL, וכפתורים, שדות וכרטיסים בסיסיים.
- דף זמני אחד שמציג את הלוגו והסלוגן, לבדיקת הגופנים, הצבעים וה-RTL.
- **הקמת פרויקט Supabase `budgi-dev` בהדרכה צעד אחר צעד:** ה-AI מנחה את המשתמש לפתוח את הפרויקט ולהעתיק את פרטי החיבור ל-`.env`. אין לבקש מהמשתמש להדביק Secrets בצ'אט.
- `.env.example` עם שמות המשתנים בלבד, והעתקה ל-`.env` לפי `CLAUDE.md`.
- **חיבור Vercel בהדרכה צעד אחר צעד:** חיבור ה-Repository, הגדרת Production Branch ל-`production` (ענף שעדיין לא קיים), והגדרת משתני Preview שמצביעים ל-`budgi-dev`.

### Definition of Done
- [ ] הפרויקט נבנה בהצלחה (`build`) ללא שגיאות.
- [ ] הדף הזמני נטען מקומית, בעברית וב-RTL, עם הגופנים והצבעים הנכונים.
- [ ] פרויקט `budgi-dev` קיים, והאפליקציה המקומית מתחברת אליו.
- [ ] `.env.example` קיים ואינו מכיל ערכים אמיתיים; `.env` מוחרג מ-Git.
- [ ] `Vitest` ו-`Playwright` מוגדרים וריצת בדיקה בסיסית עוברת.
- [ ] לאחר דחיפה ל-`main`, נוצרת ב-Vercel גרסת Preview שעובדת ומחוברת ל-`budgi-dev`.
- [ ] Production Branch ב-Vercel מוגדר ל-`production`, ולא נוצר Production Deployment.

- Smoke Tests לאחר הפריסה.
